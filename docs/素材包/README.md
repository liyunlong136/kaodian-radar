# 素材包 · 使用说明

| 文件 | 给谁用 | 怎么用 |
|---|---|---|
| `素材包_示例资料合集.md` | **Qoder** | 整个文件作为上下文/附件喂给 Qoder。**这 5 份资料会变成站点内置的示例知识库** |
| `素材包_示例问题与期望答案.md` | **Qoder + 你自己** | ⚠️ **必须和资料合集一起喂给 Qoder**（它要照着实现引用块结构，同时照着实现那 4 个预置问题）② 后半部分的**验收清单**是你自测用的 |
| `素材包_给Qoder的第一句话.md` | **Qoder** | 三个代码块按顺序用：第一轮需求描述 → v1 出来后挑第二轮修改要求 → 跑通后发部署要求 |

## 为什么给你准备了这些

**1. 解决"打开就能用"（评分②，最致命的一条）**
官方评分原文：*"核心流程是否走得通：打开就能用，不需要看说明书"*。
所以站点必须**自带示例资料 + 自带示例问题**——评委点开就能点一下看到效果。如果设计成"请先上传你的文件"，评委手上没文件，打开就是空白页，直接判不合格。

**2. 解决"问题是否真实"（评分①）**
资料内容是你正在学的机器学习 / 线性代数 / 概率论，示例问题也是真实会问的（"过拟合该调正则化还是换模型"）。**原创编写，非教材原文**，同时满足官方"必须为原创"的要求。

**3. 解决"Qoder 使用深度"（评分④）**
`素材包_给Qoder的第一句话.md` 里的需求描述是**照官方文档示例句式写的**（官方示例："说明谁会使用、要解决什么问题、需要展示哪些信息，以及用户可以进行哪些操作"）。评委看的就是你的需求描述质量。

**4. 解决"不要在浏览器存数据"（技术陷阱）**
资料末尾和第一句话里都写了硬性要求：**示例数据必须打包进站点，不能存在 localStorage**。官方文档原文："采用浏览器本地存储的数据不会随站点发布自动同步给其他用户。"

**5. 解决"Qoder 自己编题"（2026-11-25 实测踩到）**
只喂《素材包_示例资料合集.md》的话，Qoder 会自己编 4 个示例问题。它编的题漏掉了唯一考"跨章节多引用"的第 3 题（"过拟合该调正则化还是换模型"），还编了一道"RAG 为什么强调段级引用"指向虚构的论文摘要 —— 那篇摘要里未必写了段级引用，召回会很弱。
**后果：《素材包_示例问题与期望答案.md》里的期望答案和验收清单全部对不上，素材包等于白做。**
→ **两个文件必须一起喂。** 见《素材包_给Qoder的第一句话.md》顶部的用法说明和末尾的【第三轮 · 收尾要求】。
